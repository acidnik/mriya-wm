# Архитектура Mriya WM

Документ описывает текущее состояние кода. Цели проекта — в [README](../README.md).

## Что уже работает (итерация 1)

- Композитор запускается **вложенно** (nested): окно внутри текущей Wayland-сессии,
  как `niri --nested`. Никакого доступа к DRM/udev пока не нужно.
- Поднимается собственный Wayland-сокет (`wayland-N`), клиенты подключаются к нему.
- Поддерживаются протоколы: `wl_compositor`, `wl_subcompositor`, `wl_shm`,
  `xdg_wm_base` (toplevel + popup), `wl_seat` (клавиатура и указатель),
  `wl_output` + `zxdg_output_manager_v1`, `wl_data_device` (copy/paste, drag&drop).
- Окна отображаются без серверных декораций (SSD нет, клиенты рисуют свои CSD).
- Размещение новых окон — каскадом от левого верхнего угла (см. `src/shell.rs`).
- Рендер: `GlesRenderer` (EGL/GLES2), кадр рисуется по требованию
  (когда сцена изменилась), а не постоянным циклом.

## Запуск

```sh
cargo run -- -c foot          # внутри запустится foot
cargo run                     # просто пустая сессия
RUST_LOG=debug cargo run      # подробный лог
```

Сокет печатается в лог (`Mriya WM is ready socket=wayland-N`). Процессы,
запущенные самим композитором через `--command`, получают правильный
`WAYLAND_DISPLAY` автоматически. Для запуска вручную из другого терминала:

```sh
WAYLAND_DISPLAY=wayland-N foot
```

Завершить сессию: `Super+Esc` или закрыть окно композитора в родительской сессии.

## Горячие клавиши

| Комбинация | Действие |
|---|---|
| `Super+ЛКМ` + перетаскивание | переместить окно |
| `Super+ПКМ` + перетаскивание | изменить размер (правый нижний угол) |
| `Super+q` | попросить активное окно закрыться |
| `Super+Esc` | завершить сессию композитора |

Клик по окну поднимает его и передаёт фокус. Клиентские запросы на
move/resize (из CSD) тоже обрабатываются.

## Структура кода

```
src/main.rs              разбор аргументов, инициализация, запуск бэкенда
src/state.rs             Mriya — всё состояние композитора, Wayland-сокет,
                         обработка диспетчеризации клиентов, фокус
src/backend/nested.rs    бэкенд winit: окно родительской сессии, рендер кадра
src/handlers/            реализации протоколов Smithay
  mod.rs                 seat, data_device, output
  compositor.rs          wl_compositor/wl_shm, обработка commit
  xdg_shell.rs           xdg_wm_base: toplevel/popup, move/resize запросы
src/input.rs             обработка ввода от бэкенда, фильтр горячих клавиш
src/keybindings.rs       таблица горячих клавиш
src/shell.rs             политика размещения окон
src/grabs/               интерактивное перемещение и ресайз окон
```

## Решения, которые стоит помнить

- **`Space<Window>` из Smithay** используется как модель стека окон: позиция +
  порядок наложения. Для стекинг-WM (цель проекта) это ровно то, что нужно;
  тайлинг, если появится, будет надстраиваться сверху.
- **Рендер по требованию**: `Mriya::request_redraw()` ставит флаг,
  бэкенд превращает его в `request_redraw()` окна winit. Без этого композитор
  крутил бы полный кадр постоянно.
- **`WAYLAND_DISPLAY` переопределяется только после инициализации winit**,
  иначе бэкенд подключился бы к нашему же ещё не работающему сокету.
- **Damage tracker** (`OutputDamageTracker`) уже создан, но в `submit()`
  пока отдаётся полный прямоугольник окна: частичный урон — следующий шаг.
- Курсор пока не рисуется: во вложенном режиме его рисует родительский
  композитор, клиентские курсоры (`wl_cursor_image`) игнорируются.

## Следующие шаги

1. Курсор: `wl_cursor_image` → своя отрисовка (`CursorImageStatus` уже
   собирается в `SeatHandler::cursor_image`).
2. Частичный урон на кадр (`submit(Some(&damage))` из damage tracker + buffer age).
3. Заголовки/декорации: либо SSD в стиле xfwm4 (цель проекта — темы XFCE),
   либо `xdg-decoration` с серверной стороной.
4. Конфиг в kdl: раскладка клавиатуры, горячие клавиши, правила окон.
5. `xdg-activation`, `primary-selection`, `fractional-scale`, layer-shell
   (панели XFCE), затем udev/DRM-бэкенд для запуска на TTY.
6. XWayland — чтобы запускать X11-приложения.
